# 本地化（i18n）与文本管线

仓库里**不保存任何游戏文本**。引擎内部所有文本都是 **UTF-8**，用稳定的*键*标识，只通过 i18n 目录显示。原版写死的 Big5、
printf 格式和控制码只存在于一个地方：导入层 `crates/newpal-assets/src/legacy/`。其余所有代码（虚拟机、渲染器、游戏逻辑、
语言包、模组）看到的都是带一点点行内标记的 `String`。

## 文本管线

```
原版安装目录（只读，原地）                          引擎
 talk*.dat 脚本 (Big5 + %C %N %S %G ...) ---\
 g*.dat 数值表 (Big5 名称 / 描述) ------------+-> legacy/  decode_text + from_legacy   -> 键 -> UTF-8 标记文本
 <locale>/StringDB.txt (UTF-8, printf, $1) --/   （唯一了解 Big5 / % 控制码的模块）          |
 NewPAL_Release.exe（只取 SHA-256 作构建标识）                                                v
                                       I18n 目录（BCP-47 语言链、分层、转换器、缺失日志）
                                                       |  message::format  ({1} {n, plural, ...}，CLDR 规则)
                                                       v
                                       markup::parse -> 说话人、带样式的行、提示点 -> VM Dialogue -> TextRenderer（字体栈、换行）
```

* **导入（`legacy/`）**：`big5.rs`（唯一使用编解码器的地方）、`markup.rs`（原版控制码 -> 标记）、
  `stringdb.rs`（字符串表 + printf -> 消息语法，id -> 类别键）、`build.rs`（用 exe / 数值表的 SHA-256 识别构建）、
  `source.rs`（运行时的 `TextSource`，以及所有键的导出）。
  `tests/text_policy.rs` 是 CI 检查：不得使用 Big5 / 编解码器，VM 和游戏代码不得调用解码函数，代码里（`src/`、`examples/`）
  不得出现中日韩字符，`legacy/` 之外不得出现作为窗口标题的字符串字面量。
* **目录（`i18n/`）**：键、分层、语言链、回退、转换器、字体、换行。
* **使用方**：`newpal-vm` 收到 `Dialogue { name, lines, cues, raw, original }`（说话人来自 `<speaker>`，
  不处理分隔符和冒号）；`newpal-game` 负责绘制，并用 `ui:dialogue.name_sep` 添加分隔符。

## 行内标记 v1（语言包和模组里写的内容）

| 标记 | 含义 | 原版控制码 |
|---|---|---|
| `<color=N>..</color>` | 颜色索引 0-9，可嵌套 | `%C<d>`、`$<d>` |
| `<br/>` | 换行 | `%N` |
| `<page/>` | 等待按键，换新页 | `%P` |
| `<instant/>` | 其后不使用打字机效果 | `%K` |
| `<speed=N/>` | 打字机延迟档位 | `%S<d>` |
| `<glyph=N/>` | 字形绘制模式（含义未确认） | `%G<d>` |
| `<speaker>Name</speaker>` | 对话的说话人 | 第一行 `Name：%N` |
| `<ctl=X>` / `<ctl=XN>` | 尚未建模的原版控制码（`%L %D %B %A`），原样保留 | |

有些指令在文本前带有二进制操作数字节（里面含 `%`），导入层会检测并跳过（`legacy::binary_prefix`），所以目录里不会出现 U+FFFD。

转义：`<<` = `<`，`{{` / `}}` = 花括号。`%` 就是普通字符。
`%S`/`%G`/`%K`/`%P` 会被解析成**提示点**（`Dialogue.cues`，带行和列）；渲染器暂时不执行它们
（原版语义来自反编译的绘制循环：`%K` 设置“立即显示”标志，`%S<d>` 保存延迟 `default*2 + d*2`，`%G<d>` 选择绘制模式）。

## 消息：占位符和复数（ICU MessageFormat 子集）

`{name}`、`{1}`（按位置）、`{n:4}` / `{n:-4}` / `{n:04}`（宽度）、
`{n, plural, =0 {none} one {# item} other {# items}}`、`{g, select, f {..} other {..}}`。
整数的复数类别遵循 CLDR（`zero one two few many other`）：无复数的中日韩 / 东南亚语言、类英语的默认规则、法语 / 葡萄牙语、
俄语 / 乌克兰语、波兰语、捷克语 / 斯洛伐克语、阿拉伯语（`message::plural_category`；添加语言只需加一个分支）。
原版的 printf 格式在导入时转换：`%d %s %-3d` -> `{1} {2} {3:-3}`。

API：`I18n::t(key)`、`t_fmt(key, args)`、`render(key, args)`（已解析）、`tr(key, original)`、`ui(name)`。

## 键

| 键 | 文本 |
|---|---|
| `talk:<脚本>:<位置>` | 对话指令（脚本内字节偏移的 4 位以上十六进制）；带标记 |
| `name:<原版说话人>` | 说话人名称 |
| `item|magic|hero|monster|level:<id>:name` / `:desc` | `gitem gmagic ghero gmon glevel` 记录 |
| `ui:<name>` | 引擎界面文字（内置，见下） |
| `sys: ui: menu: battle: shop: msg: name: err:` `<id>` | 原版自带的字符串表（`StringDB.txt`）；数字是原版 id；类别是按 id 范围做的固定分类（`legacy/stringdb.rs`） |

Steam 版（695630）：`battle` 218、`menu` 152、`shop` 14、`msg` 22、`name` 14、`sys` 7、`ui` 70（外加 5 个内置引擎键）、
`err` 189（调试 / 错误信息，优先级低）；对话 6660 行。`newpal-i18n info` 会打印你安装里的数字。

## 原版文本真正在哪

exe 里**没有**可用的界面文字（所有 Big5 候选都是噪声）。Steam 版在每个语言文件夹（`zh-Hant`、`zh-Hans`、`en`）里带一份 UTF-8 的
`StringDB.txt`，exe 按 Steam 语言（`schinese` / 区域码 0x804 -> `zh-Hans`；0x404 -> `zh-Hant`；其他 -> `en`）选择文件夹并解析
（`<id><空格或=><文本>`，`;` 开头为注释）。`zh-Hans` 是真正的简体翻译（菜单、战斗、商店、消息、角色名）；
`en` 只是 `zh-Hant` 的逐字节拷贝（并没有英文）。菜单界面是 PNG 图片（`Resource/*_BTN_*.png` 等），
图上写死的文字只能靠替换图片来本地化。
因此导入层在运行时读取玩家自己的 `StringDB.txt`（从不复制），用 SHA-256（exe 和数值表）识别构建（未知构建也能用，只给提示），
并把与原版完全相同的条目视为未翻译。

## 语言包格式

```
lang/<locale>/lang.toml     # [meta] + 可选的 [strings]
lang/<locale>/*.toml        # 更多 [strings]；按文件名顺序合并，后者覆盖前者
lang/<locale>/fonts/*.ttf   # 可选
lang/<locale>/t2s.tsv       # 可选的转换表
```

```toml
[meta]
name    = "简体中文"
markup  = "1"                   # 字符串语法版本（省略 = 旧的 %C/%N 语言包，加载时升级并给出警告）
inherits = "en"                 # 默认：去掉地区后的标签（en-GB -> en）
fonts   = ["fonts/Body.ttf", "system:segoeui.ttf"]
wrap    = "word"                # "char"（zh-Hant 的 CJK 默认）| "word"（其他默认）
convert = "t2s.tsv"             # 字符映射（或 "opencc:t2s"），用于没有译文的文本（派生语言）

[strings]
"talk:104:0012" = "<speaker>Li</speaker><color=5>Hello</color>"
"battle:1099"   = "Victory"
"shop:1637"     = "Total {1}  Balance {2}"
"ui:dialogue.name_sep" = ": "
```

值为空表示*未翻译*（导出的模板可以安全加载）。

**为什么用 TOML（而不是 Fluent）：** 键是扁平的稳定 id，值是短字符串，TOML 正好对应，不需要额外机制；注释、多行字符串和 diff
在任何编辑器里都好用，`toml` 已经是依赖，模组作者也不用学新语法或新工具。Fluent 能多提供的两样东西，复数 / 选择器和参数，
已由上面用 CLDR 规则实现的 ICU 风格子集覆盖，而且这也是多数翻译工具（Weblate、Crowdin、Lokalise）能导入的标准。
如果以后需要术语 / 属性或性别链，可以在 TOML 加载器旁边再加一个 `.ftl` 加载器，仍然落在同一个“键 -> 字符串”目录后面，
其他部分都不用改。

## 查找顺序

1. 模组的 `text/talk/<n>.json`（旧格式，与语言无关；旧的 `%C`/`%N` 值加载时会升级）
2. 模组语言包 `<mod>/lang/<locale>/`
3. 来自 `--lang-dir`、`newpal.toml` 里的 `lang_dir`、exe 旁的 `lang/`、`%APPDATA%\NewPAL-Reborn\lang` 的语言包
4. 引擎内置的该语言链文本（`i18n/builtin/<locale>.toml`，只有 `ui:`；我们自己写的文字）
5. 玩家自己的安装为该语言附带的文本（`<game>/<locale>/StringDB.txt`）
6. 该语言的转换器作用于原文
7. 原文（zh-Hant）。在非原版语言下，每个键会记录一次日志（`I18n::missing()`、`--lang-missing <file>`）。

语言链：标签本身，然后是 `inherits` / 去掉地区的标签。标签是 BCP-47，会规范化
（`zh_TW` = `zh-Hant`，`zh-CN` = `zh-Hans`，`zh` = `zh-Hans`）。有内置文本或随游戏附带表的语言（`en`、`zh-Hans`、`zh-Hant`）
不需要语言包就能选择。

## 选择和切换

`--lang <标签>` > `newpal.toml` 里的 `language = "<标签>"` > `NEWPAL_LANG` > `zh-Hant`（原版）。
`--list-langs` 列出语言。**F12** 在运行时切换。`--ui-sheet out.png --ui-cat battle|menu|shop|msg|ui|sys|err`
会把所选语言的游戏自带字符串渲染成图（这些界面本身还没做）。

## 字体与换行

每种语言的字体栈：语言包 `fonts` -> 模组 `fonts/dialog.ttf` -> （zh-Hant：游戏的 CT.ttf）-> 该文字的系统字体 -> 游戏的 CT.ttf ->
通用 CJK 系统字体；每个字符取第一个有该字形的字体。换行：`char`（句末标点悬挂）或 `word`。

## 繁体 -> 简体

`convert = "t2s.tsv"` 会对每一行没有译文的文本应用字符 / 短语映射（最长匹配，只处理标签之间的文本）。
要完整转换，用 `--features opencc` 构建并设置 `convert = "opencc:t2s"`。

## 翻译工作流

```
newpal-i18n info                                                    # 构建标识、字符串表、数量
newpal-i18n export --out D:\work\lang --locale en --with-source     # 仅限本地，绝不要提交
# 编辑 D:\work\lang\en\talk_1.toml、battle.toml、menu.toml、shop.toml ... 填写译文
newpal-i18n check  --lang-dir D:\work\lang --locale en
newpal-i18n ui-list --locale en --cat shop --lang-dir D:\work\lang   # 引擎会显示什么
newpal --lang en --lang-dir D:\work\lang --lang-missing missing.txt
```

`export` 覆盖所有对话（扫描会越过结束标记继续，所以只能通过跳转到达的代码也包含在内）、说话人名称、数值表、
游戏的字符串表和引擎界面。`--with-source` 会把原文写成 `#>` 注释，并写一个 `.gitignore`（`*`）；
工具拒绝写入游戏文件夹。

## 迁移旧的语言包和模组

为第一版写的语言包 / 模组覆盖（`%C6`、`%N`、`Name:%N`）仍然可以加载：含旧控制码的值会在加载时升级并给出警告。
要永久改写：`newpal-i18n migrate --from <旧目录> --out <新目录>`（`*.toml` 语言包会加上 `markup = "1"`，
`text/talk/*.json` 覆盖也会被改写；注释和未改动的字符串保持不变）。
