# Localisation (i18n) and the text pipeline

The engine keeps **no game text** in the repository. Inside the engine all text is **UTF-8**, identified by a
stable *key*, and shown only through the i18n catalog. The original game's hard-coded Big5, printf formats and
control codes exist in exactly one place: the import layer `crates/newpal-assets/src/legacy/`. Everything else
(VM, renderer, game logic, language packs, mods) sees `String`s with a small inline markup.

## Text pipeline

```
original install (read-only, in place)            engine
 talk*.dat scripts (Big5 + %C %N %S %G ...) --\
 g*.dat tables (Big5 names / descriptions) ----+-> legacy/  decode_text + from_legacy   -> key -> UTF-8 markup
 <locale>/StringDB.txt (UTF-8, printf, $1)  --/   (only module that knows Big5 / %-codes)        |
 NewPAL_Release.exe (SHA-256 build id only)                                                       v
                                       I18n catalog  (BCP-47 locale chain, layers, converter, missing log)
                                                       |  message::format  ({1} {n, plural, ...}, CLDR rules)
                                                       v
                                       markup::parse -> speaker, styled lines, cues -> VM Dialogue -> TextRenderer (font stack, wrap)
```

* **Import (`legacy/`)**: `big5.rs` (the only codec use), `markup.rs` (original control codes -> markup),
  `stringdb.rs` (string table + printf -> message syntax, id -> category key), `build.rs` (exe / table SHA-256
  build identification), `source.rs` (the runtime `TextSource` and the export of every key).
  `tests/text_policy.rs` is the CI check: no Big5 / codec use, no VM / game call of the decoders, no CJK
  characters in code (`src/`, `examples/`) and no string literal as a window title outside `legacy/`.
* **Catalog (`i18n/`)**: keys, layers, locale chain, fallbacks, converters, fonts, wrapping.
* **Consumers**: `newpal-vm` receives `Dialogue { name, lines, cues, raw, original }` (speaker from
  `<speaker>`, no separator or colon handling); `newpal-game` draws and adds the separator from `ui:dialogue.name_sep`.

## Inline markup v1 (what packs and mods contain)

| markup | meaning | original code |
|---|---|---|
| `<color=N>..</color>` | colour index 0-9, nests | `%C<d>`, `$<d>` |
| `<br/>` | line break | `%N` |
| `<page/>` | wait for a key, fresh page | `%P` |
| `<instant/>` | no typewriter for the rest | `%K` |
| `<speed=N/>` | typewriter delay level | `%S<d>` |
| `<glyph=N/>` | glyph draw mode (meaning unconfirmed) | `%G<d>` |
| `<speaker>Name</speaker>` | speaker of a dialogue | first line `Name：%N` |
| `<ctl=X>` / `<ctl=XN>` | original code without a modelled meaning (`%L %D %B %A`), kept verbatim | |

Some instructions carry binary operand bytes (containing a `%`) in front of the text; the import layer detects and skips them (`legacy::binary_prefix`), so no U+FFFD reaches the catalog.

Escapes: `<<` = `<`, `{{` / `}}` = braces. `%` is an ordinary character.
`%S`/`%G`/`%K`/`%P` are parsed into **cues** (`Dialogue.cues`, with line and column); the renderer does not act on
them yet (the original semantics came from the decompiled draw loop: `%K` sets an "instant" flag, `%S<d>` stores
a delay `default*2 + d*2`, `%G<d>` selects the draw mode).

## Messages: placeholders and plurals (ICU MessageFormat subset)

`{name}`, `{1}` (positional), `{n:4}` / `{n:-4}` / `{n:04}` (width), `{n, plural, =0 {none} one {# item} other {# items}}`,
`{g, select, f {..} other {..}}`. Plural categories follow CLDR (`zero one two few many other`) for
integers: no-plural CJK / SEA languages, English-like default, French / Portuguese, Russian / Ukrainian, Polish,
Czech / Slovak, Arabic (`message::plural_category`; add a language by adding an arm). The original printf formats
are converted at import: `%d %s %-3d` -> `{1} {2} {3:-3}`.

API: `I18n::t(key)`, `t_fmt(key, args)`, `render(key, args)` (parsed), `tr(key, original)`, `ui(name)`.

## Keys

| key | text |
|---|---|
| `talk:<script>:<pos>` | dialogue instruction (4+ hex digits of byte offset in the script); markup |
| `name:<original speaker>` | speaker name |
| `item|magic|hero|monster|level:<id>:name` / `:desc` | `gitem gmagic ghero gmon glevel` records |
| `ui:<name>` | engine UI strings (built in, see below) |
| `sys: ui: menu: battle: shop: msg: name: err:` `<id>` | the original game's own string table (`StringDB.txt`); the number is the original id; the category is a fixed classification by id range (`legacy/stringdb.rs`) |

Steam build (695630): `battle` 218, `menu` 152, `shop` 14, `msg` 22, `name` 14, `sys` 7, `ui` 70 (+5 built-in engine keys), `err` 189 (debug / error messages, low priority); dialogue 6660 lines. `newpal-i18n info` prints the numbers for your install.

## Where the original text really lives

The exe contains **no** usable UI text (all Big5 candidates are noise). The Steam build ships one UTF-8
`StringDB.txt` per language folder (`zh-Hant`, `zh-Hans`, `en`) and the exe picks the folder from the Steam
language (`schinese` / locale 0x804 -> `zh-Hans`; 0x404 -> `zh-Hant`; else `en`) and parses it
(`<id><space or =><text>`, `;` comments). `zh-Hans` is a real Simplified translation (menus, battle, shop, messages,
character names); `en` is a byte copy of `zh-Hant` (no English). The menu screens are PNG images
(`Resource/*_BTN_*.png` ...), so their baked-in text can only be localised by replacing the images.
The import layer therefore reads the player's own `StringDB.txt` at runtime (never copied), identifies the build
by SHA-256 (exe and tables; an unknown build still works, with a note), and treats a shipped entry identical
to the original as untranslated.

## Pack format

```
lang/<locale>/lang.toml     # [meta] + optional [strings]
lang/<locale>/*.toml        # more [strings]; merged in file-name order, later wins
lang/<locale>/fonts/*.ttf   # optional
lang/<locale>/t2s.tsv       # optional converter table
```

```toml
[meta]
name    = "English"
markup  = "1"                   # string syntax version (omit = old %C/%N packs, upgraded on load with a warning)
inherits = "en"                 # default: tag minus its region (en-GB -> en)
fonts   = ["fonts/Body.ttf", "system:segoeui.ttf"]
wrap    = "word"                # "char" (CJK default for zh-Hant) | "word" (default otherwise)
convert = "t2s.tsv"             # char map (or "opencc:t2s") for text that has no translation (derived locales)

[strings]
"talk:104:0012" = "<speaker>Li</speaker><color=5>Hello</color>"
"battle:1099"   = "Victory"
"shop:1637"     = "Total {1}  Balance {2}"
"ui:dialogue.name_sep" = ": "
```

An empty value means *not translated* (exported templates are safe to load).

**Why TOML (and not Fluent):** keys are flat, stable ids and values are short strings, which is what TOML maps to
with no extra machinery; comments, multi-line strings and diffs work in any editor, `toml` is already a
dependency and modders need no new syntax or tooling. The two things Fluent would add - plurals / selectors and
parameters - are covered by the ICU-style subset above using CLDR rules, which is also the standard most
translation tools (Weblate, Crowdin, Lokalise) import. If terms / attributes or gender chains are ever needed,
a `.ftl` loader can be added next to the TOML loader behind the same `key -> string` catalog; nothing else changes.

## Lookup order

1. mod `text/talk/<n>.json` (legacy, locale independent; old `%C`/`%N` values are upgraded on load)
2. mod language packs `<mod>/lang/<locale>/`
3. language packs from `--lang-dir`, `lang_dir` in `newpal.toml`, `lang/` next to the exe, `%APPDATA%\NewPAL-Reborn\lang`
4. engine built-ins of the locale chain (`i18n/builtin/<locale>.toml`, `ui:` only; our own words)
5. text the player's own install ships for the locale (`<game>/<locale>/StringDB.txt`)
6. converter of the locale applied to the original text
7. original text (zh-Hant). In a non-original locale this is logged once per key (`I18n::missing()`, `--lang-missing <file>`).

Locale chain: tag, then `inherits` / the tag minus its region. Tags are BCP-47, canonicalised (`zh_TW` = `zh-Hant`,
`zh-CN` = `zh-Hans`, `zh` = `zh-Hans`). A locale that has built-ins or a shipped table (`en`, `zh-Hans`, `zh-Hant`)
is selectable without a pack.

## Selecting and switching

`--lang <tag>` > `language = "<tag>"` in `newpal.toml` > `NEWPAL_LANG` > `zh-Hant` (original).
`--list-langs` lists locales. **F12** switches at runtime. `--ui-sheet out.png --ui-cat battle|menu|shop|msg|ui|sys|err`
renders the game's own strings of the selected language (the screens themselves are not built yet).

## Fonts and wrapping

Font stack per locale: pack `fonts` -> mod `fonts/dialog.ttf` -> (zh-Hant: game CT.ttf) -> system fonts for the
script -> game CT.ttf -> a generic CJK system font; per character the first font with a glyph. Wrapping: `char`
(closing punctuation hangs) or `word`.

## Zh-Hant -> zh-Hans

`convert = "t2s.tsv"` applies a char/phrase map (longest match, only the text between tags) to every line without a
translation. For a complete conversion build with `--features opencc` and set `convert = "opencc:t2s"`.

## Translator workflow

```
newpal-i18n info                                                    # build id, string tables, counts
newpal-i18n export --out D:\work\lang --locale en --with-source     # local only, never commit
# edit D:\work\lang\en\talk_1.toml, battle.toml, menu.toml, shop.toml ... fill in values
newpal-i18n check  --lang-dir D:\work\lang --locale en
newpal-i18n ui-list --locale en --cat shop --lang-dir D:\work\lang   # what the engine would show
newpal --lang en --lang-dir D:\work\lang --lang-missing missing.txt
```

`export` covers all dialogue (the sweep continues past end markers, so code only reachable by jumps is included),
speaker names, tables, the game's string tables and the engine UI. `--with-source` writes the original text as `#>`
comments and a `.gitignore` (`*`); the tool refuses to write into the game folder.

## Migrating old packs and mods

Packs / mod overrides written for the first version (`%C6`, `%N`, `Name:%N`) still load: values that contain old
codes are upgraded on load with a warning. To rewrite them permanently:
`newpal-i18n migrate --from <old dir> --out <new dir>` (`*.toml` packs get `markup = "1"`, `text/talk/*.json`
overrides are rewritten too; comments and untouched strings are preserved).
